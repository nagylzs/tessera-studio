# Store screenshots

The same story on every store, told with the same demo data: open a
file, see the pivot, shape it, save it. Plain screenshots of the app,
no device frames, no captions painted over them (captions would need
14 translations each; the listing texts already tell the story).

English only for now: every store shows the default language's
screenshots for the locales that have none. Localised sets can come
later; they would need the demo data's labels translated too.

## Demo data

`demo/` is generated by `dart run tool/demo_data.dart` (fixed seed, a
rerun writes identical files):

- `sales.csv` — 3,000 orders of 2025: Date, Region, Country, Category,
  Product, Channel, Units, Revenue. Opens through the schema page.
- `Sales by quarter.tsnp` — rows Region → Country, columns the quarter of
  Date, sum of Revenue; Europe and North America expanded. The wide
  screens start from it.
- `Sales 2025.tsnp` — rows Region → Country sorted by revenue, largest
  first, sum of Revenue; all regions but the smallest expanded. Narrow
  enough for a phone in portrait. The phone screens start from it.

A snapshot opens straight on the workbench (no schema page) with its
pivot, so most shots need no tapping at all.

On a phone the "Show values as" submenu covers the whole screen, so the
phone set shows the sheet instead.

Files go to `<set>/<nn>-<name>.png`, e.g. `play-phone/2-fullscreen.png`.

Google Play also wants two graphics, both here:

- `play-feature-graphic.png` (1024 × 500), rendered from
  `feature-graphic.svg`: the icon and the name on the tessera green,
  beside tablet shot 1 at half size. No other words: Play shows the
  default language's graphic in every language without its own, and
  Japanese or Chinese text would need CJK fonts this machine lacks.
  `cd store/screenshots && rsvg-convert feature-graphic.svg | magick -
  -alpha off PNG24:play-feature-graphic.png` (after retaking that shot).
- `play-icon.png` (512 × 512): `rsvg-convert -w 512 -h 512
  ../tessera/icon/tessera-icon.svg`, then `magick … PNG32:…` (Play asks
  for 32-bit with alpha); full bleed, Play rounds it.

Rules as of October 2026 — check them again at upload time:

- **Google Play:** PNG or JPEG, no alpha, ≤ 8 MB; each side 320–3840 px
  and the long side at most twice the short one (the emulator's
  1080 × 2400 phone is too long: override its size). 1080 px or more
  on the short side and at least 4 screenshots make the app eligible
  for promotion. Tablets: 16:9 or 9:16. Also required: the 512 × 512
  icon and the 1024 × 500 feature graphic (above).
- **Microsoft Store:** PNG, ≥ 1366 × 768, up to 3840 × 2160, < 50 MB.
  Taken on Windows so the window frame is the real one, with the
  portable zip from a manual CI run (the CI's MSIX is the Store upload
  and does not install). What worked (2026-10-11): a 1920 × 1080 screen
  at **150 %** scaling (at 100 % the pivot fills only the left half),
  the taskbar set to hide automatically (else the Total row is cut
  off), the window maximized, the app's language set to English and
  its theme to Light (it follows Windows otherwise), then Win+Shift+S
  → window: 1920 × 1080. The app remembers language and theme, so set
  Dark and Hue levels only for the last shot. A snapshot keeps no
  changes, so reopening it undoes a stray click (a "Show values as"
  item chosen while closing the menu).
- **Apple:** PNG or JPEG, no transparency. One 6.9" iPhone set and one
  13" iPad set cover all devices; the Mac takes 16:10 sizes from
  1280 × 800 to 2880 × 1800.

## Recipes

### Xvfb (desktop set, README)

The desktop session exports `GDK_SCALE=2` and `GDK_DPI_SCALE=0.5`
(the owner's 4K monitor): unset both, or the app renders at 2× and the
1440 × 900 window shows a 720 × 450 layout. `GSETTINGS_BACKEND=memory`
keeps the owner's GNOME text scaling out too. Settings go in a scratch
`XDG_DATA_HOME`, written before the start:

```bash
X=<scratch>/xdg; mkdir -p $X/eu.nagylzs.tessera_studio
echo '{"settings:themeMode":"dark","settings:gridStyle":"hueLevels"}' \
  > $X/eu.nagylzs.tessera_studio/shared_preferences.json
Xvfb :5 -screen 0 1600x1000x24 & XPID=$!
env -u GDK_SCALE -u GDK_DPI_SCALE DISPLAY=:5 XDG_DATA_HOME=$X \
  GSETTINGS_BACKEND=memory LIBGL_ALWAYS_SOFTWARE=1 LANG=en_US.UTF-8 \
  LC_ALL=en_US.UTF-8 build/linux/x64/release/bundle/tessera_studio \
  $PWD/store/screenshots/demo/sales-quarters.tsnp & APID=$!
WID=$(DISPLAY=:5 xdotool search --class tessera_studio | tail -1)
DISPLAY=:5 xdotool windowsize $WID 1440 900 windowmove $WID 0 0
ffmpeg -f x11grab -draw_mouse 0 -video_size 1440x900 -i :5.0+0,0 \
  -frames:v 1 shot.png
kill $APID $XPID
```

Delete the scratch `XDG_DATA_HOME` between shots: a reopened file
restores its stored layout, which is not what the snapshot holds.

### Emulator (Google Play sets)

Headless and read-only, so nothing persists between runs; always
`adb -s emulator-5554` (the owner's tablet may be connected too). A
release build (`flutter build apk --release`, `adb install -r`): no
debug banner, and the real performance.

```bash
~/Android/Sdk/emulator/emulator -avd Medium_Phone_API_36.1 -read-only \
  -no-snapshot-save -no-window -no-audio -no-boot-anim \
  -gpu swiftshader_indirect &
A="adb -s emulator-5554"
$A shell wm size 1080x1920; $A shell wm density 420      # phone, 9:16
# Medium_Tablet is landscape already: wm size 2560x1440 (16:9), density
# stays 320 (1280 x 720 dp: the editors layout)
# clean status bar: 10:00, full battery and signal, no notifications
$A shell settings put global sysui_demo_allowed 1
$A shell am broadcast -a com.android.systemui.demo -e command enter
$A shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 1000
$A shell am broadcast -a com.android.systemui.demo -e command battery -e level 100 -e plugged false
$A shell am broadcast -a com.android.systemui.demo -e command network -e mobile hide
$A shell am broadcast -a com.android.systemui.demo -e command network -e wifi show -e level 4 -e fully true
$A shell am broadcast -a com.android.systemui.demo -e command notifications -e visible false
```

Open the demo files the way a user would, through a content Uri (see
CLAUDE.md for the MediaStore id lookup):
`adb push store/screenshots/demo/*.tsnp store/screenshots/demo/sales.csv
/sdcard/Download/`, then `am start -n
eu.nagylzs.tessera_studio/.MainActivity -a android.intent.action.VIEW
-t <type> --grant-read-uri-permission -d content://media/external/file/<id>`.
The theme and the grid style are set in the app's menu (a release
build has no `run-as`). Taps with `adb shell input tap x y` work on
the emulator, a long press is `input swipe x y x y 800`, and `adb
shell uiautomator dump` lists Flutter's semantics with bounds (menu
items, dialog options) — no guessing coordinates.

Things that get in the way:
- Demo mode does not hide existing notification icons (the tablet
  boots with Safety Center ones): `cmd statusbar expand-notifications`,
  tap "Clear all" (find it with `uiautomator dump`), `cmd statusbar
  collapse`.
- The first full screen in a boot shows the system's "Viewing full
  screen" hint; tap "Got it" and take the shot again.
- Android back with a chip menu open closes the page under it (the
  sheet, or the file) along with the menu: reopen the file rather than
  pressing back.
- Reopening the same file with `am start` while it is open only
  delivers the intent (`onNewIntent`); `am force-stop` first for a
  fresh pivot. `adb exec-out screencap -p` writes RGBA: strip the alpha
for Play with `magick shot.png -alpha off PNG24:shot.png`.

Afterwards: `$A emu kill`.

### Simulator (App Store iPhone and iPad sets)

Xcode 27 has no Simulator app: **DeviceHub**
(`/Applications/Xcode.app/Contents/Applications/DeviceHub.app`) shows
the simulators, and the owner clicks there (never script clicks on the
owner's desktop). Fresh devices leave the owner's own simulators alone:

```bash
I=$(xcrun simctl create "Tessera iPhone 6.9" \
  com.apple.CoreSimulator.SimDeviceType.iPhone-17-Pro-Max \
  com.apple.CoreSimulator.SimRuntime.iOS-27-0)   # iPad: …iPad-Pro-13-inch-M5-12GB
xcrun simctl boot $I && xcrun simctl bootstatus $I -b
xcrun simctl spawn $I defaults write -g AppleLanguages -array en-US
xcrun simctl spawn $I defaults write -g AppleLocale -string en_US
xcrun simctl status_bar $I override --time 9:41 --dataNetwork wifi \
  --wifiMode active --wifiBars 3 --cellularMode active --cellularBars 4 \
  --batteryState discharging --batteryLevel 100   # "charged" draws a bolt
xcrun simctl ui $I appearance light               # dark for the last shot
flutter run -d $I    # debug only: "Release mode is not supported for simulators"
```

- **No DEBUG banner without a code change:** the VM service that `flutter
  run` prints takes HTTP GETs — `curl <url>getVM` for the main isolate's
  id, then `curl "<url>ext.flutter.debugAllowBanner?isolateId=<id>&enabled=false"`
  (the toggle DevTools uses).
- **Open the demo files without taps:** `xcrun simctl openurl $I
  "file://<scratch copy of demo/>/Sales%202025.tsnp"` delivers them like
  "Open with" (cold or warm); `sales.csv` the same way.
- **Capture:** `xcrun simctl io $I screenshot raw.png` (the device's own
  size), then `magick raw.png -fill "$(magick raw.png -format
  '%[pixel:p{8,8}]' info:)" -draw 'rectangle 0,0 5,5' -alpha off
  PNG24:shot.png`: the capture has an alpha channel, and the debug build
  in the simulator has a 1-point black square in the top-left corner
  (not on a device: TODO.md, Done).

Things that got in the way (2026-10-20):
- The iPad runs apps in windows (the app's name in the status bar, a
  resize handle in the corner): Settings → Multitasking & Gestures →
  Full Screen Apps, then rotate to landscape in DeviceHub.
- iPadOS draws a bevel around the clock while the Simulator window is
  not focused — the owner typing "done" in the terminal is enough — and
  while a menu is open. Refocus DeviceHub before the capture; for the
  "Show values as" shot the top 64 rows came from shot 1 (identical
  elsewhere: `magick compare -metric AE` on the strips gave 0).
- iPad pointer hover effects: park the pointer on empty space.
- An "Open with" while a sheet is open leaves the sheet over the new
  file (TODO.md): close sheets and dialogs before the next `openurl`.

Afterwards `xcrun simctl shutdown $I` (and `delete` once the listing is
uploaded).

### Mac (Mac App Store set)

On the owner's 5K display (2560 × 1440 points, Retina) a window of
1440 × 900 points is 2880 × 1800. A build only for the shots, with two
temporary changes reverted right after `flutter build macos --release`
and never committed:

- `PRODUCT_BUNDLE_IDENTIFIER = eu.nagylzs.tessera-studio.shots` in
  `macos/Runner/Configs/AppInfo.xcconfig`: its own sandbox container,
  so fresh settings and the owner's left alone (another app's container
  cannot be read from the shell);
- in `MainFlutterWindow.swift`, after the existing `setFrame`:
  `self.setFrame(NSRect(x: 240, y: 200, width: 1440, height: 900),
  display: true)`.

Copy the built app to a scratch folder and open each file with `open -a
<copy> <file>`. The owner takes the shots (capturing from the shell
needs Screen Recording permission): click the window's title bar (an
inactive window has grey traffic lights), ⌘⇧4, Space, Option-click the
window; for the menu shot, open the menu and capture without leaving
the window. The title bar follows the Mac's appearance, not the app's
Theme (TODO.md): switch the Mac to Light or Dark and leave the app on
System. Processing: `magick raw.png -alpha extract -threshold 99.9%
-format %@ info:` gives the opaque window (`2880x1800+X+Y`, also when
the shadow was included); crop it, then fill the transparent rounded
corners by compositing it over a canvas in the bottom edge's colour
with the top 40 rows in the title bar's colour, `-alpha off PNG24:`.
Afterwards quit the copy, `lsregister -u` it and delete it (else it
stays in Finder's "Open With").
